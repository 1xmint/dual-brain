# Package Tiers

This pack is designed as a modular system.

The current package you are reading is the flagship / Pro edition. Smaller
tiers are created by removing modules, not by changing the core truth of how the
system works.

## Current Product Posture

Right now, the honest public product line is:

- one flagship / Pro package
- no cut-down public tier shipped yet

That is intentional.

The package is stronger as one clear flagship than as several premature smaller
tiers with blurry boundaries.

## Pro / Flagship

Includes:

- front-door docs and orientation
- repo-memory and repo-doc templates
- agent workflow guide
- lightweight collaborator guidance
- tool-translation guidance
- platform setup guidance
- verified capability and routing guidance
- chaos-recovery guidance
- advanced repo-ops guides
- examples
- full public orchestration system

This is the best fit if you want the whole package and do not want to guess what
to leave out.

## What Buyers Should Know

- Not every repo needs the orchestration system on day one.
- Many users should start with `AGENTS.md`, a few core docs, and the
  lightweight workflow.
- Orchestration is included because some projects genuinely need it, not because
  every collaborator should install it.

## Smaller Tiers

Smaller tiers are optional future derivatives, not current promises.

If they ship later, they should remove advanced modules while keeping the basic
operating system intact.

Typical building blocks:

- `AGENTS.md` and core repo-doc templates
- workflow guides
- lightweight collaboration guidance
- examples
- optional orchestration layer

Current rule:

- ship the flagship cleanly first
- only carve smaller tiers after real buyer usage proves where the clean cut
  lines are

## What All Tiers Deliberately Do Not Do

Every tier, including Pro, stays inside honest limits:

- no guaranteed security outcome
- no compliance coverage
- no promise that every model can safely run every orchestration layer
- no claim that every buyer needs the heaviest workflow
