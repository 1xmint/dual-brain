# User Support Profile

Use this when the system needs to decide how much guidance, explanation, and
reassurance to give a buyer without slowing production down.

## Core Truth

Different buyers need different amounts of support.

The system should adapt to that deliberately, not by tone luck.

The goal is not "be verbose."
The goal is:

- keep fast users fast
- keep newer users confident
- keep shaky users supported
- keep learning optional instead of forced
- keep all support earned by evidence and usefulness

## Preferred Home

Store durable support truth in:

- `OPERATOR-PREFERENCES.md`

Do not bury repeated support needs in chat history if they clearly recur.

## Recommended Fields

- support posture: `shipping / guided / teaching`
- explanation depth: `minimal / standard / fuller`
- reassurance preference: `low / medium / high`
- jargon tolerance: `low / medium / high`
- wants optional learning callouts: `yes / no`
- confidence state: `confident / cautious / shaky / exploring`
- doctor note preference: `compact / standard`

## Posture Meanings

### Shipping

Best for:

- experienced developers
- users who want speed first
- users who already trust the structure

Default behavior:

- short recommendation
- minimal explanation
- direct execution after approval

### Guided

Best for:

- users who want support without losing speed
- users trying orchestration seriously for the first time
- users who want one extra sentence of confidence-building context

Default behavior:

- recommendation-first
- one short why
- one short what-happens-next line
- no unnecessary teaching lecture
- no empty reassurance

### Teaching

Best for:

- newer users
- shaky users
- users explicitly learning their workflow

Default behavior:

- plain language first
- translate jargon
- briefly explain why the move exists
- keep a fast path available

## Final Rule

The user should not have to earn support by already understanding the system.
The system should adapt early enough that the interaction itself builds
confidence.
That support should make the reply truer, clearer, or easier to act on, not
just softer.
