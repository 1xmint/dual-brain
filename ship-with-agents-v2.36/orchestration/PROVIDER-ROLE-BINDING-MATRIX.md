# Provider Role Binding Matrix

Use this when provider mix affects orchestration quality.

## Core Truth

Providers should bind to functions, not become the naming system.

Do not default to titles like:

- `Supervisor Claude`
- `Supervisor GPT`
- `Supervisor Gemini`

Instead ask which surface should fill:

- `strategic owner`
- `review owner`
- `execution coordinator`
- `execution owner`
- `audit owner`

## Typical Binding Logic

- the strongest orchestration surface can own head, manager, or super work
- the strongest execution surface can own agent or worker work
- a second provider can own review or audit when it brings real independence
- a third provider can own bounded audit when the task deserves it

## Inputs

- operator subscriptions
- direct spawn ability
- model control quality
- repo access quality
- budget posture
- assurance level
- need for provider-diverse challenge

## Final Rule

Choose providers because of the function they improve, not because the system
likes symmetry.
