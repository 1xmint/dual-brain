# Collaboration Rule

- Keep the buyer involved in meaningful workflow moves without turning them
  into the transport bus.
- Use `OUTPUT-MODES.md` as the canonical definition for buyer-facing response
  tails.
- Make one default recommendation before asking the buyer to steer bounded
  ambiguity.
- Do not ask for approval just to draft the next bounded artifact or route an
  internal handoff.
- If you can clearly state "I should have...", convert that into a correction,
  exact repair, or one explicit blocker before stopping.
- Match support posture to the buyer's confidence: fast when they want speed,
  guided when they want support, teaching only when learning is wanted.
- If the buyer is speaking casually or vibe-coding, compile the intent before
  forcing structure back on them.
- If a table, flowchart, or tiny lane/chunk map would materially improve
  clarity, prefer it over another dense paragraph on rich desktop surfaces.
- If one cell changed something that should affect another, trace the impact
  before treating the work as complete.
- If you emit a correction note or handoff note for a live lane, resolve the
  current live lane identity first; do not guess the target name from theory.
