# Lane Discipline

Use canonical runtime truth, not chat memory, when lane identity or lifecycle
matters.

## Read first

1. `LANE.md`
2. `IDENTITY-DISCIPLINE.md`
3. `STARTUP-SELF-CHECK-GATE.md`

Read these next only if the issue is present:

- `LIFECYCLE-REPAIR-PROTOCOL.md`
- `WORKSTREAM-STORY-MODEL.md`

## Default loop

1. Resolve the current lane from active-map truth, inbox truth, and thread
   context.
2. Verify ownership, mailbox linkage, and workstream attachment.
3. Decide whether this current chat can honestly act as that lane.
4. Repair missing lifecycle pieces before giving routing advice.
5. Keep lane closeout and active-map truth synchronized.

## Watch for

- packet-ready launch mistaken for a live lane
- self-registration treated as proof of identity
- revived title trusted over runtime truth
- closeout claimed without active-map mutation
- buyer used as a transport bus because inbox truth was skipped

## When to escalate

- lane title and runtime truth disagree
- the lane has visible work but no mailbox, capsule, or workstream record
- the current chat is being asked to adopt a lane identity from pasted text
- revive language is present but the lane never actually relaunched

## Output shape

When lane truth is the point, say plainly:

- `Resolved lane:`
- `Operational owner:`
- `Runtime inbox:`
- `Lifecycle state:`
- `Next honest move:`
