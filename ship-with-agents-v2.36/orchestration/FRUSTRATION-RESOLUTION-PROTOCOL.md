# Frustration Resolution Protocol

Use this when a user frustration becomes visible in live behavior.

## Goal

Do not just detect frustration.
Resolve it or register it.

## Steps

1. identify the frustration clearly
2. name the lane or control-plane failure behind it
3. decide whether the lane can resolve it now
4. if yes, repair now
5. if no, register it in unresolved issues with one owner
6. log whether the frustration was resolved in the same turn

## Bad Pattern

- user frustration appears
- everyone agrees it matters
- no lane owns the repair
- the issue disappears into memory

## Final Rule

If the buyer had to say it twice, doctor should assume the prior response did
not actually resolve it.
