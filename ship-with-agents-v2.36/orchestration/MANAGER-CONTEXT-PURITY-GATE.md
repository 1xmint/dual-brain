# Manager Context Purity Gate

Use this before letting one manager own or review multiple live supers or
multiple hot workstreams.

## Core Truth

A manager can be technically available while already too scattered to be a
high-quality review brain.

The question is not:

- can this manager still reply?

The question is:

- can this manager still challenge with clean context and real independence?

## Safe Multi-Super Cases

One manager may cover multiple supers when most of these are true:

- only one workstream is truly hot
- the others are parked, waiting, or light-touch
- repos are disjoint
- assurance is `A0` or `A1`
- review depth is shallow
- the manager is not actively iterating launch truth for more than one cell

## Dedicated Manager Cases

Treat a dedicated manager or dedicated review cell as required when any are
true:

- two or more workstreams are actively changing at `A2` or `A3`
- the same manager is flipping between unrelated repo truths
- launch boundaries are moving in more than one live cell
- the manager is becoming the serialized bottleneck for multiple supers
- the manager is doing deep challenge plus closeout plus new scoping on
  different cells at once

## Warning Signs

- the manager keeps re-reading the same background because context is muddy
- reviews become generic instead of artifact-specific
- one super waits while the manager is buried in another repo
- the manager starts approving based on summary instead of evidence
- user momentum drops because one review lane is overloaded

## Preferred Fixes

Use the lightest honest fix:

1. park one workstream
2. keep one manager but narrow it to one hot cell
3. split into multiple manager-scoped cells
4. add an audit brain only for the risky cell

## Final Rule

If one manager is carrying enough unrelated hot review truth that challenge is
starting to feel shallow, context purity is already degraded.
