# Replan Trigger Gate

Use this when live truth may have changed enough that the current plan or lane
shape is no longer the smartest one.

## Replan Signals

Replan when any of these are true:

- a key assumption was disproved
- a shared contract changed materially
- a blocker cleared and unlocks new parallelism
- a sibling workstream made the current slice obsolete or redundant
- a new frustration reveals the current UX path is not good enough
- the current topology now looks too heavy or too light

## Do Not Replan For

- cosmetic edits
- status-only updates
- small evidence additions with no structural effect

## Final Rule

Replan because the world changed, not because a lane feels uneasy.
