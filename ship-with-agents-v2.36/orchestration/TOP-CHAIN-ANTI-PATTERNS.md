# Top-Chain Anti-Patterns

Use this to catch head/manager failures that poison everything below them.

## Head Anti-Patterns

- value-blind routing: launching work without a clear reason it matters now
- sequencing drift: letting a later phase preempt a sharper prerequisite
- topology habit: using the same lane structure regardless of risk or scope
- defer-without-truth: saying "later" without naming what is blocked or why
- silent budget drift: acting as if every premium surface is free and available

## Manager Anti-Patterns

- paper audit: repeating the super summary without real challenge
- topology blur: letting one manager quietly carry too many hot review cells
- bridge omission: naming the next owner without producing the actual bridge
- execution-report acceptance: treating a good build report as equivalent to a
  good closeout state
- buyer labor leak: making the buyer transport, approve, or assemble things the
  system could already carry

## Shared Top-Chain Anti-Patterns

- guessing from lane names instead of reading live truth
- allowing continuity files and human-facing output to disagree
- escalating structure before simpler reuse options are tested
- letting unresolved user frustration disappear instead of becoming a tracked
  pattern

## Final Rule

If a lane below head or manager repeatedly sounds confused, stalled, or overly
ceremonial, inspect the upstream decision quality before blaming the lower
layer first.
