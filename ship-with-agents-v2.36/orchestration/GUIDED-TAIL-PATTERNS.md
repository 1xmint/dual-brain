# Guided Tail Patterns

Use this when the response needs to feel more supportive without becoming
heavier.

## Core Truth

The tail is where the user decides whether the system feels clear or cold.

Use short supportive framing, not long extra prose.
Support should add truth, clarity, or easier action.

## Better Tail Shapes

### `No user action needed:`

Good shape:

- what changed
- why that is enough for now
- what will happen next

Example:

`No user action needed: I routed the handoff internally and updated the work
doc, so the next owner can pick up from clean truth instead of chat memory.`

### `Recommended next move:`

Good shape:

- one recommendation
- one short evidence-bound supportive reason
- what happens after `go`
- the exact bridge in the same turn if another lane is the real next owner
- if the buyer may still need to act, a short `For you:` block with the
  easiest action first
- if a live parent pickup trigger is enough, say `done` or `read your inbox`
  plainly and say when no terminal copy is needed
- if the buyer needs one tiny trigger now and a different tiny return later,
  say both in compact plain language
- if the buyer needs to say literal words, render those words in tiny
  standalone copy blocks instead of prose-only instructions unless the current
  surface truly cannot show a clean block
- keep only the exact copyable words inside the block; keep reasons and
  bookkeeping outside it
- if a live lane must be nudged for work to resume now, show that tiny action
  before bookkeeping about inbox/mail/doc updates
- compress bookkeeping into one short line unless the bookkeeping artifact is
  itself the recommended next move
- if the lane quietly repaired minor runtime hygiene while doing the real work,
  keep that to one short line or omit it when it adds no buyer value

Example:

`Recommended next move: let manager review this before launch. That keeps the
next step small and safe. The exact manager packet is below so you can move
immediately if you want.`

### `Decision needed from buyer:`

Good shape:

- what the real choice is
- why it belongs to the buyer
- the recommended default if one exists

## Anti-Patterns

- technically correct but emotionally flat endings
- `No user action needed:` with no sense of what happens next
- `Recommended next move:` with no supportive framing at all
- supportive framing that adds no new truth
- praise or reassurance that could fit almost any turn
- `Recommended next move:` that still makes the user ask what to paste and
  where
- completion summaries that never translate into a plain `For you:` action
- making the user guess whether saying `done` is enough
- making the user guess whether they need to copy anything from the terminal
- making the user guess what to say now versus later when two live lanes are
  involved
- telling the buyer what to say without giving a ready copy block when one-line
  block would clearly be easier
- prose like `tell s8-social: read mail and stay on Home only` when the user
  should really get a one-click copy-ready block
- too much coaching text after the action tail
- opening with "I wrote this to inbox/mail" when the user really needs a wake
  trigger first
- giving a mini menu of several plausible next moves after the lane already
  knows its default recommendation
- leading with a self-repaired mailbox or inbox gap when the real story is the
  product work that continued successfully

## Final Rule

The tail should feel clear, steady, and earned.
And if a human action is required, the easiest correct action should appear
first.
