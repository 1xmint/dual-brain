# docs/inbox/

This is the front door for new ideas -- the first durable artifact
in the idea lifecycle.

## What belongs here

Any idea worth keeping gets an inbox entry before it goes anywhere
else. The entry does not need to be good; it needs to exist with a
thesis, an owner, and a status so it can be triaged.

Sparks happen in friction logs, chat history, GitHub Discussions.
None of those count as being in the lifecycle. An idea enters the
lifecycle the moment it has an `i-YYYYMMDD-slug.md` file here with
valid frontmatter. Before that it is still just a spark.

Sources that feed inbox:
- Manual creation (default)
- Friction-log promotion: head identifies a pattern and promotes
  it with `source: friction:<session>:<F#>`
- GitHub Issues/Discussions tagged `inbox`: manual mirror with
  `source: github:<repo>#<num>`

## Frontmatter requirements

Required fields:
- `id` -- always required; format `lc-YYYYMMDD-slug`; never changes
- `stage: inbox`
- `owner` -- who is driving this idea; ghost owners are anti-pattern 8
- `created` -- creation date; never changes
- `last_touched` -- updated on every meaningful edit
- `source` -- where this idea came from

Optional fields (fill as known):
- `topic` -- freeform tag for sibling-detection at Decision stage
- `links` -- other ids this idea relates to
- `skipped_stages` -- with reason if stages will be skipped
- `cost_estimate`

## Status conventions

Inbox entries carry one of these statuses in the body (not frontmatter):

- `Status: new` -- captured, not yet triaged
- `Status: triaged` -- thesis confirmed, fitness check passed, owner assigned
- `Status: stale` -- 30 days no-touch; surfaces in weekly triage
- `Status: promoted -> lc-YYYYMMDD-slug` -- moved forward in lifecycle

## Triage cadence

Weekly triage is the head's responsibility. If it lapses two weeks,
surface it as friction. Capturing without triaging is anti-pattern 3
(Dead Inbox): it makes the folder a graveyard of never-acted sparks
that erode trust in the system.

The gate from Inbox to Brainstorm requires: thesis stated, fitness
check passed, someone owns it. Do not promote without those three.

## File naming

`i-YYYYMMDD-slug.md` where YYYYMMDD is the creation date (locked after
first promotion) and slug is lowercase-hyphenated, max 6 words.

## Example entry

```
---
id: lc-20260426-friction-aggregation
stage: inbox
owner: head
created: 2026-04-26
last_touched: 2026-04-26
source: friction:head-session-4:F3
topic: friction-pipeline
links: []
skipped_stages: []
---

Status: triaged

Multiple sessions have noted that friction entries go unread after
session close. Pattern first appeared in h1-friction.md. Head
promoted to inbox after three occurrences across separate sessions.

Next step: brainstorm whether automatic aggregation or structured
head review solves this better.
```
