# Perspective Sweep Gate

Use this before narrowing into one plan, one packet, or one implementation
path for any meaningful task.

## Core Truth

Chats often fail not because they cannot reason deeply, but because they lock
onto one angle too early.

A short perspective sweep usually improves quality by surfacing:

- a simpler framing
- a hidden risk
- a missing owner
- a buyer-experience problem
- a better sequence
- a missing existing artifact that already answers part of the problem

This is a quality guard, not a ritual tax. Use it for meaningful work, not
for trivial mechanical turns.

## When To Use It

Prefer a perspective sweep when one or more are true:

- the task is ambiguous
- the task changes workflow shape or ownership
- the task may affect buyer UX
- the task may have hidden downstream effects
- the task is package/shared-system work
- the lane is about to recommend a specific path with confidence

You usually do not need a full sweep for:

- tiny obvious fixes
- pure mechanical edits
- already-resolved follow-through inside the same bounded move

## Minimum Sweep

Before narrowing, quickly check these angles:

1. buyer perspective
2. operator/setup perspective
3. current owner / neighboring owner perspective
4. implementation perspective
5. review / risk perspective
6. existing-artifact perspective

If relevant, also check:

6. portability / packaging perspective
7. continuity / recovery perspective
8. opportunity / simplification perspective

## Good Questions

- From the buyer's perspective, what would feel confusing, heavy, or cold?
- From the operator/setup perspective, what assumptions might be local, not
  universal?
- From the current/neighboring owner perspective, who should actually do the
  next step?
- From the implementation perspective, what is the smallest honest move?
- From the review/risk perspective, what could go wrong if we narrow too soon?
- From the packaging perspective, is this teaching one operator quirk as if it
  were general law?
- From the existing-artifact perspective, what docs, slices, plans, reviews,
  checkpoints, inbox updates, or repo resources already contain truth I should
  read before proposing anything?

## Output Effect

The sweep does not need a giant visible section.

Its job is to improve the chosen output:

- better recommendation
- better launch shape
- better routing target
- better warning
- better scope boundary
- better reuse of work already done

## Final Rule

Do not confuse early certainty with whole-picture understanding.
When the task is meaningful, sweep angles before you lock the answer.
